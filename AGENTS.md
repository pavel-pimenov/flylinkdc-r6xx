* Все изменения добавляй в файл HISTORY.md
* Всю сборку, установку сборочных зависимостей и проверки выполняй только в Docker на базе Ubuntu 26.04. Не устанавливай пакеты сборки на хост.
* Состав инструментов фиксируй в Dockerfile; не ограничивайся ручной установкой в запущенном контейнере.
* Цель: Windows x64 exe со статически слинкованными сторонними библиотеками и runtime компилятора. Системные DLL Windows допустимы; Linux-библиотеки из apt не подходят для линковки Windows exe.
* Команды из корня репозитория:
  - Образ: `docker build --tag flylinkdc-build:ubuntu26.04 - < Dockerfile`
  - Сборка: `docker run --rm --user "$(id -u):$(id -g)" --mount "type=bind,source=$(pwd),target=/src" flylinkdc-build:ubuntu26.04`
  - Проверка скрипта: `docker run --rm --user "$(id -u):$(id -g)" --mount "type=bind,source=$(pwd),target=/src,readonly" flylinkdc-build:ubuntu26.04 shellcheck build-win.sh`
* Артефакты сохраняй в build-win; контейнер запускай с UID/GID пользователя, чтобы не оставлять root-owned файлы.
* После успешной линковки проверяй импорты через `x86_64-w64-mingw32-objdump -p build-win/flylinkdc.exe` внутри контейнера и отдельно проверяй запуск на Windows. Успешная сборка Docker-образа не означает, что приложение собрано или работает.
* Текущий Dockerfile содержит инструменты кросс-компиляции, но не готовые Windows-библиотеки проекта. Для полной сборки нужно настроить сборку зависимостей и решить совместимость ATL/MSVC; не подменяй отсутствующий функционал заглушками.
* Правила наименования C++ 
  - Для членов класс используй в имени префикс m_
  - Для глобальных или статических перменных используй в имени префикс g_
  - Для параметров функций используй префикс p_
  - Для Локлаьных переменных используй префикс l_
